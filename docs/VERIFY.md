## 四、已知限制（不是 bug）

- **单人单设备**：没有账号与云同步，数据在这台手机的这个浏览器里。换机/清缓存前必须导出 JSON。
- **照片不进备份**：`exportJSON` 只带 `photoCount` 计数。
- **取消拍照不等于中断请求**：点取消只是丢弃在途结果。
- **识别质量依赖模型**：结果永远先进可编辑清单；命中内置 159 条食物库时用库值覆盖模型估算。
- **运动消耗是 MET × 体重 × 时长粗估**；营养值取自常见公开数据，非实验室级。
- **并发双击**：同一日期快速连点 3 次以上保存，仍可能出现一次「数据冲突」提示（已做一次重试自愈）。
- **`#/debug` 的往返测试是手动按钮**，不随「运行自检」自动跑——自动跑会在打开页面时清空数据。

### 待真机确认：更新时切走应用（用户 2026-10-22 决定延后）

**背景**：下载在原生后台线程（`hms-update` Executor）里跑，切到别的应用/锁屏**不会中断**；
但从最近任务划掉应用会杀进程、下载丢失（无断点续传）。
**真正的风险点**：拉起安装器走 `host.runOnUiThread(() -> host.startActivity(...))`，
而 **Android 10+ 限制后台应用启动界面**——若用户切走时恰好下载完成，安装界面可能不弹出。
代码里**只有**「等待未知来源授权」那条路有 `onResume()` 续拉保护（`pendingInstall` 有值才重试），
**普通路径没有等价保护**。

**用户决定**：先不单独发版；下次更新时实测。若体验不好，随下个版本一起修。

**修法（约 10 行，需重新打 APK）**：把「已下载完成但尚未拉起安装器」也记成 pending，
在 `MainActivity.onResume()` 时自动补拉，与现有的授权等待路径复用同一套逻辑。

**为什么影响变小了**：下载源已切到 CloudBase 静态托管，1.79MB 实测 1.2 秒（原 GitHub Pages 5.5 KB/s 需 317 秒），
"切走"这个窗口实际很难撞上。

### 后端 fuzz 套件的正确跑法（2026-10-23 定）

**主套件单独跑有一个盲区**：如果平台把网关请求体上限从 102400 **调小**，主套件发现不了——
它那两条超限探针（1MB / 8MiB+1）在任何调小幅度下**照样返回 413**，断言照样通过。

所以例行回归要跑**两条**：

```powershell
node tests/fuzz.api.mjs                                    # 干跑，0 请求
$env:HMS_FUZZ_API='1'; node tests/fuzz.api.mjs             # 主套件，约 96 请求
$env:HMS_FUZZ_API='1'; $env:HMS_FUZZ_CEILING_TARGETS='102400,102401'; node tests/fuzz.api.mjs --ceiling
                                                           # 边界探针，仅 5~7 请求 ← 唯一的"上限被调小"报警器
```

**为什么客户端阈值不会自动跟随**：`js/sync.js` 的 `PUSH_BODY_LIMIT_BYTES=100000` 是
`GATEWAY_MAX_REQUEST_BYTES(102400) − 2400` 算出来的**常量**，与平台真实值无运行时耦合。
平台调小上限后**必须人工同步**这两个数字，否则客户端会发出越界请求（表现为网关 413、界面只说"网络不可用"）。

**跑完记得清理测试账号**（套件不自清）：
```sql
DELETE FROM users WHERE username_lower LIKE 'fuzz_%';
DELETE FROM users WHERE username_lower IN ('fz3');
```
（`tcb db execute` 一次只跑一条语句；跑完核对 `users` 计数回到只有你自己的账号。）
