## 二、必须在手机上人工确认（按顺序做，5 分钟）

1. **安装**：Chrome 打开站点 → ⋮ → 添加到主屏幕。图标应是青绿渐变心形无白边，名称「HMS 健康」，点开后无地址栏（standalone）。
2. **离线冷启动**：装好后开飞行模式，从桌面图标冷启动 → 必须能打开（这条验的是 `sw.js` 预缓存是否齐全，曾经漏过 `js/pure.js`，已修并升到 `hms-v1.0.1`）。再逐个点五个 tab。
3. **建档案**：设置 → 个人档案（性别/生日/身高/活动量）→ 保存 → 回今日页，应出现热量环与目标数值。目标若不合理可手动覆盖。
4. **记体重**：体重页录入 → 折线、BMI、历史出现；同日再录一次应**覆盖**而不是两条（这是唯一修过的并发缺陷，值得重试一次）。
5. **拍照识别**：设置里填 Key → 点「测试连接」应显示「连接成功」→ 饮食页「拍照识别」→ 应直接进后置相机 → 5~20 秒出结果 → 清单里改克数、删一项、看合计 → 选餐次保存 → 今日页热量与宏量随之变化。
6. **失败分支**：把 Key 改错一位 → 拍照 → 应提示「去设置检查 Key」而不是白屏或静默失败；断网再拍 → 应给「重试 / 手动添加」。
7. **手动添加**：不填 Key 也能用 → 搜索「米饭」→ 选份量 → 保存。
8. **数据往返**：设置 → 导出 JSON（存到手机）→ `#/debug` 页跑一次「导出→清空→导入」往返 → 今日页数值应与导出前一致。**注意：备份 JSON 不含照片二进制。**
9. **安全区**：全面屏手势条不应压住底部 tabbar（`env(safe-area-inset-bottom)`）；输入克数时软键盘不应挡住保存按钮。
10. **文件选择器**：国产 WebView 个别会拦 `<label>` 包隐藏 `input[type=file]` 的点击。若拍照/相册点了没反应，这是唯一需要改的交互点（改成真按钮 + `input.click()`），改一处即可。

## 三、已知限制（不是 bug）

- **单人单设备**：没有账号与云同步，数据在这台手机的这个浏览器里。换机/清缓存前必须导出 JSON。
- **照片不进备份**：`exportJSON` 只带 `photoCount` 计数，避免几 MB base64 把浏览器拖死。
- **取消拍照不等于中断请求**：点取消只是丢弃在途结果，请求仍在后台跑完（`analyzeFoodPhoto` 无 signal）。
- **识别质量依赖模型**：结果永远先进可编辑清单，命中内置 159 条食物库时用库值覆盖模型估算。
- **运动消耗是 MET × 体重 × 时长粗估**；营养值取自常见公开数据，非实验室级。
- **并发双击**：同一日期快速连点 3 次以上保存，仍可能出现一次「数据冲突」提示（已做一次重试自愈）。
- **`#/debug` 的往返测试是手动按钮**，不随「运行自检」自动跑——自动跑会在打开页面时清空数据。

4. 手机端重开 App 两次完成 SW 换代。
