用真实阿里百炼 Key 直接调用线上接口，不是 mock：

2. **模型可用性（重要）**：该账号**未开通** `qwen-vl-max`（`404 model_not_found`）。`GET /compatible-mode/v1/models` 列出 178 个模型，视觉类只有 `qwen3-vl-plus`、`qwen-vl-ocr`、`qwen3.5-ocr` 等。因此默认模型已改为 **`qwen3-vl-plus`**，候选清单为 `qwen3-vl-plus / qwen-vl-max / qwen-vl-plus / qwen2.5-vl-72b-instruct`。
   → 换账号或换服务商时，若识别报「模型不存在」，去设置页换候选即可，不用改代码。
3. **测试连接按钮**：真实 Key → `0.6s`，返回「连接成功，模型「qwen3-vl-plus」可用。」；坏 Key → 「API Key 无效或已过期：请到「设置 → 视觉识别」重新填写。」

## 二·五、v1.1 新增的两处交互（真机重点看）

- **体重刻度尺**：左右拖动刻度、松手吸附（kg 0.1 / 斤 0.2）、点单位 chip 切 kg/斤、左下角图标切回键盘输入。重点看：跟手程度、松手是否生硬、软键盘是否遮住保存按钮。

## 三、必须在手机上人工确认（5 分钟）

1. **安装**：Chrome 打开站点 → ⋮ → 添加到主屏幕。图标应是青绿渐变心形无白边，名称「HMS 健康」，点开后无地址栏（standalone）。
2. **离线冷启动**：装好后开飞行模式，从桌面图标冷启动 → 必须能打开（验的是 SW 预缓存是否齐全，曾经漏过 `js/pure.js`）。再逐个点五个 tab。
3. **建档案**：设置 → 个人档案 → 保存 → 回今日页，应出现热量环与目标数值。
4. **记体重**：录入 → 折线、BMI、历史出现；**同日再录一次应覆盖为一条**（这是修过的并发缺陷）。
5. **填 Key 并测试**：设置 → 视觉识别 → 粘贴 Key → 点「测试连接」，应显示「连接成功，模型「qwen3-vl-plus」可用」。
6. **拍照识别**：饮食页「拍照识别」→ 应直接进后置相机 → 5~20 秒出结果 → 可改克数/删项 → 选餐次保存 → 今日页数值随之变化。
7. **失败分支**：把 Key 改错一位 → 拍照 → 应提示去设置检查 Key；断网再拍 → 应给「重试 / 手动添加」。
8. **数据往返**：设置 → 导出 JSON → `#/debug` 页跑一次「导出→清空→导入」→ 今日页数值应与导出前一致。**备份 JSON 不含照片二进制。**
9. **安全区与键盘**：全面屏手势条不应压住底部 tabbar；输入克数时软键盘不应挡住保存按钮。
10. **文件选择器**：若点「拍照识别」没反应（个别国产 WebView 会拦 `<label>` 包隐藏 `input`），这是唯一需要改的交互点。

## 四、已知限制（不是 bug）

- **单人单设备**：没有账号与云同步，数据在这台手机的这个浏览器里。换机/清缓存前必须导出 JSON。
- **照片不进备份**：`exportJSON` 只带 `photoCount` 计数。
- **取消拍照不等于中断请求**：点取消只是丢弃在途结果。
- **识别质量依赖模型**：结果永远先进可编辑清单；命中内置 159 条食物库时用库值覆盖模型估算。
- **运动消耗是 MET × 体重 × 时长粗估**；营养值取自常见公开数据，非实验室级。
- **并发双击**：同一日期快速连点 3 次以上保存，仍可能出现一次「数据冲突」提示（已做一次重试自愈）。
- **`#/debug` 的往返测试是手动按钮**，不随「运行自检」自动跑——自动跑会在打开页面时清空数据。
